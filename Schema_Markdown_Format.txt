## Table `admins`

### Columns

| Name | Type | Constraints |
|------|------|-------------|
| `id` | `int8` | Primary Identity |
| `created_at` | `timestamptz` |  |
| `admin_email` | `text` |  |
| `admin_name` | `text` |  |

This table — not a role claim on `profiles` or the JWT — is the source of
truth for "is this user an admin". Admin-only edge functions authenticate
the caller's JWT, then check `auth.uid()`'s email against `admin_email`
here. (Use Case 19's spec text assumed a `role === 'admin'` claim; no such
column exists anywhere in this schema.)

## Functions

### `adjust_product_stock(p_product_id uuid, p_delta int, p_reason text)`

Added 2026-09-16 for Use Case 19 (Catalog Management). Atomically applies
a signed delta to `products.stock_quantity` (`SET stock_quantity =
stock_quantity + p_delta`) and logs the change to `inventory_logs`.
Raises an error if the product doesn't exist or the adjustment would take
stock below zero. `security definer`, executable only by `service_role` —
called from the `admin-catalog-stock` edge function, never directly from
the client.

Use Case 19's own spec text showed an absolute-value stock update
(`{"stock_quantity": 85}`) in its request example, but its Edge Cases
section explicitly called for atomic delta-based updates instead, to
avoid concurrent admins overwriting each other's changes. This function
implements that safer version; there is no absolute-set endpoint.

## RLS Policies

### `profiles`

| Policy | Command | Roles | Action | USING | WITH CHECK |
|--------|---------|-------|--------|-------|------------|
| `Users can update own profile` | UPDATE | public | PERMISSIVE | `(auth.uid() = id)` | — |
| `Users can view own profile` | SELECT | public | PERMISSIVE | `(auth.uid() = id)` | — |

### `cart_items`

### `categories`

| Policy | Command | Roles | Action | USING | WITH CHECK |
|--------|---------|-------|--------|-------|------------|
| `Public can view active categories` | SELECT | public | PERMISSIVE | `(is_active = true)` | — |

Renamed and tightened from the original `Public can view categories`
(`USING (true)`) on 2026-09-16: once `is_active` existed, leaving this
policy as `true` would have kept exposing soft-deleted categories to
public/storefront reads regardless of the app-level admin UI hiding them.
Admin edge functions use the service-role client and bypass RLS, so they
can still see and reactivate inactive categories.
